# TeamUP 学号注册与登录设计

现有导航继续服务三种演示身份的功能测试。学号账号的前端和 API 已实现，可在隔离环境通过直达地址试用。校内试点采用学号与独立的 TeamUP 密码，复用 FastAPI、MySQL 和 React。本文中的自动投递、运营多因素认证和正式留存策略属于校内试点部署安排。

## 本机试用与运营操作

普通页面没有账号入口。独立账号环境启动后，可以直接访问以下路径。

| 页面     | 直达路径                                    |
| -------- | ------------------------------------------- |
| 登录     | `/login`                                    |
| 注册     | `/register`，由一次性激活链接带入凭证       |
| 重置密码 | `/reset-password`，由一次性重置链接带入凭证 |
| 账号安全 | `/center/security`，登录后可改密或退出      |

在独立数据库创建专用空库和用户，并给库用户授予仅该数据库的权限。预览终端配置 `TEAMUP_AUTH_MODE=student` 和 `TEAMUP_DEMO_MODE=false`，用 `TEAMUP_DB_NAME`、`TEAMUP_DB_USER`、`TEAMUP_DB_PASSWORD` 指向独立库。`TEAMUP_SESSION_SECRET` 设置独立的随机密钥，至少 32 字节。`TEAMUP_ALLOWED_ORIGIN` 设为 `http://localhost:5181`。正式环境使用 HTTPS。当前演示终端继续沿用 `.env` 的设置。

在账号环境的 `backend` 目录执行。

```powershell
uv sync --frozen
uv run alembic upgrade head
uv run python -m app.seed --foundation-only
uv run uvicorn app.main:app --host 127.0.0.1 --port 8087
```

另开终端在 `frontend` 目录启动预览。

```powershell
$env:TEAMUP_API_TARGET = 'http://127.0.0.1:8087'
npm exec vite -- --host localhost --port 5181 --strictPort
```

在载入相同账号环境变量的后端终端，用下面的命令给已核验的同学签发链接。学号在提示时输入。激活或恢复链接通过既有的可信渠道交付本人。

```powershell
uv run python -m app.account_admin activate
uv run python -m app.account_admin reset
uv run python -m app.account_admin suspend
uv run python -m app.account_admin restore
```

预览环境的授权持有人可从本机专用配置加载变量后运行上述命令。配置中含数据库凭据和会话密钥，置于 Git 忽略的文件中。

```powershell
$teamupPreview = Get-Content ../.env.student.local -Raw | ConvertFrom-StringData
foreach ($item in $teamupPreview.GetEnumerator()) {
  [Environment]::SetEnvironmentVariable($item.Key, $item.Value, 'Process')
}
uv run python -m app.account_admin activate
```

## 注册与名片引导

1. 试点运营通过校方认可的渠道核验学籍，把与学号绑定的单次激活链接发给本人。「注册」页说明如何领取链接。后续接通校方授权的身份验证服务时，可替换发放环节，沿用账号和名片流程。
2. 打开激活链接后，注册表单只填写「学号」和「TeamUP 密码」。学号按校方规则校验并保留前导零。表单支持密码管理器、粘贴和密码显示切换，提示设置独立密码。前端从链接片段取出激活凭证后清理地址栏，由服务端在提交时校验。字段出错在原处反馈，激活链接过期时指向重新领取。
3. 验证通过后，服务端一次提交创建账号、关联业务用户并消费凭证，提交成功才建立登录会话。注册成功页提供「完善个人名片」和「稍后再说」，两个操作在手机上也直接可见。
4. 「完善个人名片」复用现有编辑页，提交按钮写「发布名片」。表单说明学院、专业与年级会显示给站内同学，QQ 只会在击掌获接受后向对方展示。比赛意向和项目经历继续选填。保存失败保留已经填写的名片内容。
5. 「稍后再说」直接进入个人中心。跳过或离开编辑器时，账号可以立即使用，个人中心保留「创建名片」入口。名片发布前，「找队友」没有这张名片。以后正常登录或刷新由个人中心显示完成状态，首次引导只在注册成功时展示一次。

新账号的默认显示名用「未设置昵称」，创建名片时提示自行填写。没有名片的账号可以浏览校内队伍和队友。沿用现有联系方式交换规则，候选人发出申请前须发布名片，队长发布招募和发出邀请前须提供 QQ。试点发布入口提供直达名片编辑的提示，避免公开招募收到申请时才发现队长缺联系方式。试点首版复用现有名片表单收集 QQ。

## 登录、会话与账号恢复

| 场景       | 行为                                                                                                                                                                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 登录       | 学号和 TeamUP 密码通过校验后，回到原请求的站内页面，直接登录默认进入个人中心。返回地址只接受应用内可访问路径。学号不存在、密码不正确或账号停用使用同一失败反馈。                                                                                                                 |
| 会话       | API 生成不可预测的随机会话令牌，数据库只存摘要。正式 Cookie 使用 `__Host-teamup_account`，设置 `Secure`、`HttpOnly`、`SameSite=Strict`、`Path=/`，全程 HTTPS。试点以 30 分钟闲置期限和 12 小时绝对期限起步，登录时换发会话。改密、退出和停用可撤销相应会话，在后续请求立即生效。 |
| 找回密码   | 输入学号后统一反馈。通过已核验的校内渠道发送短期单次链接，渠道不可用时交由有权限的人员重新核验。新密码保存、链接消费及全部会话撤销在同一事务完成。完成后提示重新登录。                                                                                                           |
| 停用与关闭 | 运营人员经授权可以停用、恢复或关闭账号并留下原因。停用时撤销会话，下架招募，公开查询过滤停用账号的名片。恢复后，已有名片重新可见，队长可按需重新上架招募。关闭账号后的业务记录保留策略随校方试点约定确定。                                                                       |

学生首版采用密码登录。密码长度支持 15 至 128 字符，有基础弱密码阻止列表。正式部署可通过 `TEAMUP_PASSWORD_BLOCKLIST` 载入本地 UTF-8 阻止列表，每行一个密码。存储使用带独立盐的 Argon2id，按部署容量压测哈希成本和验证并发数。登录、注册和重置密码按账号标识、来源分别限频，多实例共享限流计数，未知账号执行同等成本的密码校验。沿用同源写请求校验，正式会话的写操作加入会话绑定的 CSRF 校验。一次性链接打开时只展示表单，由明确的提交动作消费，避免邮件预览误用。 [NIST 密码指南](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) · [OWASP 密码存储](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) · [OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) · [OWASP 找回密码](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) · [OWASP CSRF 防护](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)

## 数据、权限与运维

| 数据                   | 设计                                                                                                                                                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `users`                | 保持现有 UUID 和昵称，继续作为名片、招募和击掌申请的关系键。                                                                                                                  |
| `student_accounts`     | 含关联的 `user_id`、唯一的规范化学号、密码哈希、账号状态和核验时间。恢复渠道限授权服务访问。学号按字符串以精确规则比较，数据库唯一约束处理并发注册。                          |
| `account_challenges`   | 激活和找回凭证，按用途绑定学号或账号，只存令牌摘要，记录有效期和消费时间。条件更新或行锁确保只消费一次，补发时让此前未使用的同用途凭证失效。                                  |
| `account_sessions`     | 按令牌摘要查询，关联用户 UUID，记录签发、闲置到期、绝对到期和撤销时间。后台清理过期记录。                                                                                     |
| `account_audit_events` | 记录账号开通、异常登录、找回、撤销与管理动作。保存事件、结果、操作者和目标的内部标识、时间、请求 ID 及必要的管理原因。日志和监控排除学号原值、密码、令牌、QQ 和恢复渠道地址。 |

- 学号只在账号服务用于登录和身份核验。本人安全页可显示掩码，公开名片、找队友、招募、简历、击掌详情及业务 `/me` 响应均排除学号。核验相关数据走独立访问权限和保留期限。
- 队长权限继续由招募的所有者 UUID 决定。运营账号独立授权并启用多因素认证，首批仅开放所需的核验、恢复、停用和审计权限，敏感管理动作记录操作者与原因。运营角色无法绕过击掌双方的联系方式权限。
- 校内试点允许访客看首页、关于和赛事介绍。找队伍、找队友和证明图片由 API 验证有效学生会话，名片的字段可见性和 QQ 的授权继续由后端判断。账号停用后，已有击掌记录可供仍有权限的参与者查看状态，停用账号的 QQ 停止通过任何详情接口提供。

## 接入现有演示环境

- 建议由服务端解析 `TEAMUP_AUTH_MODE`，取值 `off`、`demo` 或 `student`。没有显式新配置时兼容现有 `TEAMUP_DEMO_MODE`。显式冲突应启动失败。`demo` 保留三种身份和现有 Cookie，`student` 只解析正式会话，`off` 关闭两个登录入口并拒绝校内隐私数据。学生账号启用前使用独立 HTTPS 域名、数据库和密钥，避免演示名片或虚构 QQ 流入试点。
- `GET /api/v1/auth/capabilities` 提供无敏感字段的当前模式，前端据此决定显示演示切换还是登录入口。对于未启用的入口，页面和直接 API 调用都由模式约束。学生凭据不进入 `VITE_TEAMUP_MOCK`、浏览器持久存储或分析埋点。试点可暂停发放新凭证，若需立刻暂停所有注册则同时撤销未使用的激活凭证，已有学生仍可登录。
- [会话 API](../backend/app/api/routes.py) 的 `POST /demo/session` 保持旧响应。`GET /me` 区分演示会话和学生会话，演示保留 `persona`，学生返回业务 UUID、昵称和会话类型。业务路由复用统一认证依赖和现有对象级权限检查。
- [前端壳](../frontend/src/App.tsx) 负责入口和会话恢复，[请求层](../frontend/src/api/client.ts) 负责会话请求、认证错误和 CSRF。账号数据放在独立服务与 Alembic 迁移中，OpenAPI 生成接口类型。生产只初始化技能和必要的基础数据，虚构学生、队伍及联系方式只在演示库播种。

### 当前 API

以下路径相对于 `/api/v1`，继续使用现有错误结构与 `Cache-Control: no-store`。

| API                                     | 契约                                                                                                                                                                    |
| --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /auth/capabilities`                | 返回当前支持的模式和入口状态。                                                                                                                                          |
| `POST /auth/register`                   | 接收 `studentId`、`password`、`activationToken`。验证成功后开通账号，设置正式 Cookie 并返回学生会话摘要。                                                               |
| `POST /auth/login`、`POST /auth/logout` | 登录创建会话，退出撤销当前会话并清除 Cookie。                                                                                                                           |
| `POST /auth/password/reset/confirm`     | 使用运营签发的重置链接设置新密码。令牌消费时撤销既有会话。                                                                                                              |
| `POST /auth/password/change`            | 已登录用户核验旧密码后改密，撤销旧会话并要求重新登录。                                                                                                                  |
| `GET /me`、`PUT /me/profile`            | 恢复当前会话，或由本人发布和更新名片。学生会话的 `/me` 在响应头提供会话绑定的 CSRF 令牌，供客户端在写请求中提交，客户端只在内存中保留。账号注册和首次名片保存各自提交。 |

## 试点验收

| 检查       | 通过条件                                                                                                                  |
| ---------- | ------------------------------------------------------------------------------------------------------------------------- |
| 演示回归   | 三种身份仍能切换，名片、招募、击掌与 QQ 共享演示走完。账号页面直达和注册 API 在演示环境均不可用。                         |
| 注册和归属 | 正常学号通过本人凭证注册。重复提交、并发提交、过期、跨学号使用和凭证重放均无法创建第二份账号或半条记录。                  |
| 跳过和补填 | 注册后可立即跳过并浏览。刷新和再次登录不强制跳转。个人中心可补填，保存失败保留草稿，成功后才出现在「找队友」。            |
| 会话和恢复 | 刷新可恢复。超时、退出、改密和停用会正确失效。两种 Cookie 在各自环境内生效，暂停注册后现有学生可继续登录。                |
| 数据边界   | 公开响应、简历、日志与错误不含学号或凭据。无关用户无法读取联系方式。直接访问资料、证据图片和已下架招募同样遵守权限。      |
| 上线准备   | 先以合成学号在隔离环境测试。校方核验与找回渠道、数据保留规则、正式 HTTPS 和运维处置流程明确后，才向受控名单发放激活链接。 |
